## Decisions (DECIDED)
Auto-clicker lives as its own tool in Device and System. Pictures stay pictures: the reader only reads words inside them (on-device ML Kit, Latin script); describing what a picture shows stays with the brain. Approval is bound to a routine's exact content; only typing and switch steps can be pre-approved; money, wallet and password apps, risky buttons and sign-in screens always ask. The red STOP button is an accessibility overlay (no draw-over-apps permission) and sets a native kill switch that every action checks. Screens by AI Studio only; Directors write the prompts; no AI Studio work before Gate A.

## How tools were wired (the pipeline, in case it must be redone on a newer repo)
Adding an available tool touches: toolCatalog.ts (status and opens), the screen id lists (axonState.ts, storage.ts), App.tsx, AxonToolsScreen.tsx (icon), a capability and an interface registration plus main.tsx, a schema row in actionSchemas.ts (words must be dictionary headwords, at least one concept of its own, and "routine" as a noun disturbs the need-cases test), the facts fixture (tests/fixtures/toolFacts.json, with the facts regenerated by building buildLiveFacts the way tests/liveFacts.test.ts does), the golden help text (tests/fixtures/brainGolden.json, one line per capability), and the count and name lists in tests/tools.test.ts, liveFacts, resolveOptionsRunner and engineTruth. The jszip package is missing in the D47 sandbox, so a stand-in was used to run those tests; the real tests must pass in the cloud build.

## Lessons (so they are not paid for twice)
1. Shared files: never ship an older whole copy (NAP N18). Zips are held in .axon-held/ when they clash; look there when a file seems missing (the final strings file and the script were held once).
2. A relative path in a packaging script once produced oversized zips; they were caught and deleted before use. Always check a zip's file list.
3. Activation zips must come AFTER the screens they point to; the placeholder zip repairs the order if they were merged early.
4. Strict TypeScript infers types from JavaScript defaults: engine files called from .ts need a loose JSDoc parameter type.
